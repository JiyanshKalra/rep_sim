# Deal Desk Quote Simulator

Interactive quote calculator and approval simulator for enterprise sales deals, built with a FastAPI backend and a Next.js frontend. The application validates pricing tiers, calculates discounts deterministically with Decimal precision, flags deal desk approval triggers, and manages the quote lifecycle.

## What is built

- **Must build items**:
  - Interactive quote builder with real-time pricing calculation and field validation
  - Seat-based tier resolution (`STARTER`, `GROWTH`, `ENTERPRISE`) and discount caps
  - Deal desk approval trigger detection (discount > 15%, total > $25,000, or annual commitment with discount > 10%)
  - Quote saving with immutable line-item snapshots and customer name validation
  - Quote review view displaying snapshot data and catalog freshness warnings
  - Quote list view with status indicators, summaries, and navigation
  - Quote workflow state machine (`draft` -> `submitted` -> `approved` / `rejected`)
- **Should build features (implemented)**:
  - **Scenario comparison**: side-by-side comparison of quote variants with difference tags (`ScenarioComparison.tsx`, `compareLines.ts`)
  - **Explain pricing**: deterministic plain-English calculation breakdown generated by backend and rendered on preview and review (`explain.py`, `ExplanationPanel.tsx`)
  - **Draft recovery**: automatic form state persistence to `localStorage` with corrupted-state recovery (`draftStorage.ts`)

## Requirements

- Python 3.11+ (tested with Python 3.12.3)
- Node 24 (specified in `.nvmrc`)

## Quick start

1. Backend:
   ```bash
   cd backend
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   uvicorn app.main:app --reload --port 8000
   ```
   *Windows PowerShell activation*: `.venv\Scripts\Activate.ps1`

2. Frontend:
   ```bash
   cd frontend
   npm install
   npm run dev
   ```

3. Open http://localhost:3000 in your browser.

## API

| Method | Path | Purpose | Success Status |
|---|---|---|---|
| `GET` | `/api/health` | Health check | 200 OK |
| `GET` | `/api/catalog` | Products, discount tiers, and approval thresholds | 200 OK |
| `POST` | `/api/quotes/calculate` | Validate draft and compute breakdown without saving | 200 OK |
| `POST` | `/api/quotes` | Validate and persist quote draft snapshot | 201 Created |
| `GET` | `/api/quotes` | List all saved quotes (newest first) | 200 OK |
| `GET` | `/api/quotes/{id}` | Fetch saved quote snapshot and live catalog status | 200 OK |
| `PATCH` | `/api/quotes/{id}/status` | Transition quote status | 200 OK |

### Worked example (`POST /api/quotes/calculate`)

Request body:
```json
{"seats": 50, "lines": [{"sku": "ONBOARDING", "quantity": 8}], "discount_pct": 20, "annual_commitment": false}
```

Response body (200 OK):
```json
{
  "tier": "ENTERPRISE", "max_discount_pct": "30", "currency": "USD",
  "lines": [{"sku": "ONBOARDING", "name": "Implementation", "unit_price": "2500.00", "quantity": 8, "line_total": "20000.00"}],
  "subtotal": "20000.00", "discount_pct": "20", "discount_amount": "4000.00", "total": "16000.00",
  "approval_required": true, "approval_reasons": ["discount_above_15_percent"],
  "explanation": [
    "50 seats → Enterprise tier → maximum discount 30%.",
    "Subtotal $20,000.00 → 20% discount ($4,000.00) → final $16,000.00.",
    "Approval required because discount is above 15%."
  ]
}
```

### Error envelope and codes

All 4xx/5xx responses use a unified envelope: `{"errors": [{"code": "...", "field": "...", "message": "..."]}`.
Codes found in code: `seats_missing`, `seats_not_integer`, `seats_out_of_range`, `lines_missing`, `lines_not_list`, `lines_empty`, `line_not_object`, `sku_missing`, `sku_not_string`, `sku_unknown`, `sku_duplicate`, `quantity_missing`, `quantity_not_integer`, `quantity_out_of_range`, `discount_not_number`, `discount_negative`, `discount_too_many_decimals`, `discount_exceeds_tier_max`, `annual_commitment_invalid`, `customer_name_required`, `customer_name_not_string`, `customer_name_too_long`, `invalid_transition`, `malformed_request`, `not_found`, `method_not_allowed`, `http_error`, `internal_error`.

## Business rules

1. **Tiers & Caps**: STARTER (1–9 seats, max 10%), GROWTH (10–49 seats, max 20%), ENTERPRISE (50+ seats, max 30%).
2. **Cap Enforcement**: Discount exceeding tier cap is a 422 validation error (`discount_exceeds_tier_max`), not an approval case.
3. **Rounding**: Decimal only; line totals unrounded; `discount_amount` rounded to 2 places (`ROUND_HALF_UP`); `total = subtotal - discount_amount`.
4. **Approval Triggers**: Strict `>`: discount > 15%, total > $25,000, or annual commitment with discount > 10% (15%, $25,000, 10% do not trigger).
5. **Annual Commitment**: Affects approval threshold only; does not modify tier, unit pricing, or discount caps.
6. **Rule Authority**: All business logic is isolated in `backend/app/rules.py`; the frontend never computes pricing or approvals.

## Known limitations

1. **File persistence**: Local JSON file storage (`backend/data/quotes.json`) with file locking; single-process only.
2. **No authentication**: No login or user roles; any user can submit, approve, or reject quotes.
3. **Static catalog**: Catalog changes do not retroactively alter saved quotes (flagged via `catalog_status` on review).
4. **UTC timestamps**: Timestamps are generated in UTC without localized timezone formatting.
5. **Unvalidated API client responses**: Frontend trusts 2xx API payloads without runtime schema parsing.
6. **Test coverage**: Frontend tests cover pure transformation and error routing helpers; no component/browser e2e tests.
